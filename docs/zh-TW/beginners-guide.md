## 1. 什麼是 NullClaw？

**一句話總結：** NullClaw 是一個小巧、快速且安全的 AI 助理，完全在您自己的本機電腦上運作。它本身不內建 AI 模型——而是由您自行選擇並連接想要使用（且自付費用）的模型，例如 OpenRouter、OpenAI 或 Anthropic。

您可以這樣理解：

| 比喻 | 代表意義 |
|---|---|
| NullClaw 是**大腦** | 它負責聆聽、思考、規劃並採取行動。 |
| 您的 AI Provider（OpenRouter 等）是**知識引擎** | 它負責生成文字、回答問題與處理圖片。 |
| **頻道（Channel）**（Telegram、Discord 等）是您與它對話的方式 | 就像選擇傳 Email 或發簡訊一樣——頻道負責傳遞訊息。 |

**為什麼要用它，而不直接打開 ChatGPT 網站就好？**

| 使用場景 | ChatGPT | NullClaw |
|---|---|---|
| 在 Telegram 或 Discord 上與機器人對話 | 否 | 是 — 可直接連線 |
| 讓 AI 讀取與寫入您電腦上的檔案 | 極為有限 | 是 — 擁有完整權限 |
| 讓 AI 執行 Shell 指令 | 否 | 是 — 在安全的沙盒中執行 |
| 在 5 美元的樹莓派（Raspberry Pi）上運作 | 否 | 是 |
| 所有資料保留在您自己的電腦上 | 否 | 是 |
| 串接您自有的基礎設施 | 否 | 是 |
| 完全離線、不需要任何 API 金鑰 | 否 | 否 — 依然需要 API 金鑰 |

NullClaw 最適合那些希望 AI 按照自己的規則、在自己的硬體上運作，並能連接到自有工具與通訊軟體的**進階使用者（Power Users）**與**開發者**。

## 2. 您可以讓 NullClaw 做些什麼？

設定完成後，NullClaw 能處理各式各樣的任務。以下是一些日常生活化的範例：

**資訊蒐集與研究**
- 「幫我總結這個網址文章的重點」
- 「今天東京的天氣如何？」（透過網頁搜尋工具）
- 「幫我找出上週所有關於專案 X 的電子郵件」

**檔案操作**
- 「讀取我工作區裡名為 notes.md 的檔案」
- 「將我們的會議總結寫入 meeting-notes.md」
- 「把這份會議筆記附加到每日日誌的末尾」
- 「編輯 README 檔案，加上安裝說明」

**系統與 Shell 操作**
- 「檢查硬碟還剩多少儲存空間」
- 「顯示伺服器日誌的最後 50 行」
- 「執行備份指令碼，並告訴我是否成功」

**寫程式與開發**
- 「寫一個 Python 腳本讀取 CSV 並繪製長條圖」
- 「解釋這段錯誤訊息是什麼意思」
- 「為登入功能新增一個單元測試」

**自動化排程**
- 「每天早上 9 點提醒我檢查伺服器狀態」
- 「當我在 Telegram 發送包含『deploy』的訊息時，執行部署腳本」
- 「把這條重要筆記存入記憶體中，當我問起時再告訴我」

**通訊頻道**
- 「發送一則訊息到我的 Discord 頻道」
- 「回覆剛剛在 Telegram 上敲我的使用者」
- 「在我們的 Slack 頻道發布進度更新」

**硬體控制（進階）**
- 「讀取連接到樹莓派上的感測器溫度」
- 「讓 Arduino 第 13 支腳位的 LED 燈閃爍」

## 3. 心智模型：各元件如何協同運作

在開始進行任何設定前，先理解三個核心組成元件會很有幫助：

### 第 1 部分 — 對話介面（您如何與它溝通）

您有兩種主要方式與 NullClaw 互動：

**CLI 模式（命令列模式）：** 在終端機視窗中輸入訊息。適合快速任務與測試。

```bash
nullclaw agent -m "2 + 2 等於多少？"
```

**互動模式：** 保持連線開啟的連續對話連線階段：

```bash
nullclaw agent
# 接著直接輸入您的訊息
```

**閘道模式（Gateway）：** 功能最強大的架構。啟動一個監聽訊息的本地 Web 伺服器。其他程式或頻道（Telegram、Discord 等）可以連線至該伺服器，並轉發使用者的訊息。這就是讓 NullClaw 能在 Telegram 或 Discord 內即時回覆訊息的運作方式。

```bash
nullclaw gateway
# 預設執行於 http://127.0.0.1:3000
```

### 第 2 部分 — 頻道（訊息如何進出）

**頻道（Channel）** 是 NullClaw 與外部通訊軟體之間的橋樑。您可以把它想成電話線——每個頻道就是一個不同的電話號碼。

NullClaw 開箱即支援許多頻道：

| 頻道 | 連接對象 |
|---|---|
| CLI | 您的本機終端機（無外部網路連線） |
| Telegram | 您的 Telegram 機器人 |
| Discord | 您的 Discord 機器人 |
| Signal | 您的 Signal 帳號 |
| Slack | 您的 Slack 工作區 |
| WhatsApp | 您的 WhatsApp 商業帳號 |
| Email | 您的收件匣與外寄郵件 |
| Matrix | Matrix/Element 即時通訊 |
| Nostr | Nostr 去中心化通訊協定 |
| Webhook | 任何 HTTP 端點（供自訂串接） |
| IRC | IRC 聊天室 |
| Lark / Feishu | 飛書/Lark 工作區 |
| DingTalk | 釘釘工作區 |
| QQ | QQ 通訊軟體 |
| iMessage | macOS iMessage 簡訊 |
| Mattermost | Mattermost 自託管通訊平台 |

**重要安全觀念：** 預設情況下，頻道只會接受來自您指定的「核准使用者清單」中的訊息。若允許清單為空，頻道將拒絕任何人。這是刻意設計的安全防護——能防止陌生人擅自操控您的 AI。

### 第 3 部分 — 閘道（訊息路由器）

**閘道（Gateway）** 是中央樞紐，負責：
1. 從各個頻道（Telegram、Discord 等）接收訊息
2. 將訊息送交 AI 進行思考與處理
3. 將 AI 的回覆透過正確的頻道發送回去

```
使用者發送訊息
       ↓
  通訊頻道（Telegram/Discord 等）
       ↓
  閘道（位於 :3000 的訊息路由器）
       ↓
  AI 模型（OpenRouter/OpenAI 等）
       ↓
  NullClaw 大腦（思考、呼叫工具、做決策）
       ↓
  產生回覆
       ↓
  閘道 → 頻道 → 使用者收到回覆
```

預設情況下，閘道只在您的本機電腦上監聽（`127.0.0.1:3000`）。這代表電腦外部的任何人都無法直接存取它。若要允許外部存取（例如從網際網路接收 Telegram Webhook 訊息），您需要使用**網路通道（Tunnel）**——透過如 Cloudflare 或 ngrok 等服務，建立一條安全的加密通道將本地閘道暴露給外部世界。

## 4. 5 分鐘快速上手

### 步驟 1 — 取得 API 金鑰

NullClaw 需要連接 AI 模型的大腦進行思考，您必須提供相應的 API 金鑰。最簡單的起步方式是使用 **OpenRouter**，它讓您只需一個帳號就能存取市面上幾乎所有的 AI 模型：

1. 前往 [openrouter.ai](https://openrouter.ai) 並註冊免費帳號。
2. 前往 **Keys** 頁面建立一把新的 API 金鑰。請將它複製並妥善保存——金鑰只會顯示這一次。
3. （選用）為您的帳戶加值一點餘額，讓 AI 能夠實際回覆。即使儲值 5 美元也足夠讓您盡情體驗各項功能。

> **什麼是 API 金鑰？** 把它想成一把密碼。它向 AI 服務商證明您的身分並計算使用量。請務必妥善保管——任何拿到您金鑰的人都可以消耗您的帳戶額度。

### 步驟 2 — 安裝 NullClaw

**macOS / Linux（推薦方式）：**

```bash
brew install nullclaw
```

**Windows：**

從 [NullClaw Releases 發行頁面](https://github.com/nullclaw/nullclaw/releases) 下載 Windows `.zip` 壓縮檔，解壓縮後將包含的 `nullclaw.exe` 放置在您容易找到的路徑。

**從原始碼編譯（所有平台適用）：**

```bash
git clone https://github.com/nullclaw/nullclaw.git
cd nullclaw
zig build -Doptimize=ReleaseSmall
# 編譯產出的執行檔將位於 zig-out/bin/nullclaw
```

### 步驟 3 — 進行初始化設定

執行互動式設定引導精靈：

```bash
nullclaw onboard --interactive
```

精靈會詢問您幾個問題，以下是每個問題的說明：

| 問題 | 建議回答 |
|---|---|
| Provider（模型提供商） | 選擇 `openrouter` |
| API Key（金鑰） | 貼上您的 OpenRouter 金鑰 |
| Default model（預設模型） | 直接按 Enter 鍵接受建議的模型 |
| Workspace directory（工作區目錄） | 直接按 Enter 鍵使用預設路徑（NullClaw 儲存檔案的地方） |
| Gateway host（閘道主機位址） | 直接按 Enter 鍵（保持本機綁定以確保安全） |
| Gateway port（閘道連接埠） | 直接按 Enter 鍵（預設為 3000） |
| Enable channels?（啟用通訊頻道？） | 如果想先嘗試 CLI 模式，請輸入 `n` |

### 步驟 4 — 測試執行

```bash
nullclaw agent -m "你好！可以向我自我介紹一下嗎？"
```

您應該會在幾秒鐘之內收到 AI 的回覆。

### 步驟 5 — 啟動閘道服務

如果您想讓 NullClaw 開始監聽來自 Telegram、Discord 或其他頻道的訊息：

```bash
nullclaw gateway
```

您會看到日誌輸出確認閘道已經在 `127.0.0.1:3000` 順暢運作。

若要停止它，直接按下鍵盤上的 `Ctrl+C` 即可。

## 5. 記憶體（Memory）如何運作

NullClaw 內建了長期記憶體系統。這代表它能在不同的對話之間，記住您曾經告訴過它的重要事情。

### 它是如何儲存記憶的

記憶會儲存在您電腦本機的資料庫中（預設為位於 `~/.nullclaw/memory.db` 的 SQLite 資料庫）。您也可以設定 `memory.database_path` 指定其他路徑；相對路徑會從工作區目錄解析。除非您主動設定使用遠端記憶體後端，否則**絕不會將任何資料傳送到雲端**。

### 記憶操作指令類型

| 指令 | 用途 |
|---|---|
| `/memory-store <fact>` | 將某件事實存入長期記憶體 |
| `/memory-recall <topic>` | 檢索與某主題相關的記憶事實 |
| `/memory-forget <fact>` | 從記憶體中刪除特定事實 |
| `/memory-list` | 列出當前記憶體中儲存的所有項目 |
| `/scratch` | 開啟暫存筆記本以供快速記錄隨手資訊 |

### 對話範例

```
您：請記住，我伺服器的管理員密碼是 SuperSecret123。
NullClaw：好的，我已將此事實安全地存入記憶體中。

您：我之前有告訴過你關於我伺服器的什麼事情嗎？
NullClaw：您曾提到過您伺服器的管理員密碼是 SuperSecret123。
```

### 什麼時候該清理記憶體

- 您不小心分享了敏感資訊 → 使用 `/memory-forget` 或直接要求 NullClaw 將其刪除。
- 記憶內容已經過時或不準確 → 提供更新後的事實以覆寫修正。
- 您想要徹底重新開始 → 執行 `nullclaw memory purge` 清除所有記憶。

> **隱私保護須知：** 預設情況下，所有記憶體資料均完整保留在您的本機電腦上。除非您明確設定了遠端記憶體後端，否則 NullClaw 絕不會將您的對話歷史或記憶內容外洩給 AI Provider。

## 6. 保護您的系統安全

NullClaw 內建了多項安全防禦功能。您不需要了解深奧的技術細節——只要知道它們隨時在保護您的電腦即可。

### 功能 1 — 工作區隔離（它可以存取哪些檔案）

預設情況下，NullClaw 只能讀取和寫入位於特定資料夾（稱為**工作區 Workspace**）中的檔案。它無法任意存取您電腦上的整個檔案系統。這能有效防止它意外讀取或竄改敏感檔案（例如密碼檔、SSH 金鑰或個人文件）。

工作區預設路徑通常為 `~/.nullclaw/workspace/`。您隨時可以在設定檔中更改此路徑。

### 功能 2 — 沙盒保護（它可以執行哪些指令）

當 NullClaw 需要執行 Shell 指令（例如 `ls` 或 `git`）時，它會在**沙盒（Sandbox）**中執行——這是一個受限制的隔離環境，嚴格限制了指令能做的事情。它無法：
- 存取工作區以外的檔案
- 修改作業系統核心設定
- 擅自安裝軟體
- 存取其他使用者的隱私資料

### 功能 3 — 配對機制（誰可以使用閘道）

當閘道運作時，它會強制使用**配對認證（Pairing）**——這是一項安全檢查機制，要求任何連線的客戶端都必須出示有效的配對碼。這能防止未經授權的陌生人透過網路擅自向您的 NullClaw 發送指令。

### 功能 4 — 頻道允許清單（哪些人能與它交談）

每個通訊頻道都具備**允許清單（Allowlist）**——即獲准的使用者 ID 或帳號清單。只有在清單上的使用者才能透過該頻道向 NullClaw 發送訊息。若頻道清單為空，將拒絕所有人的訊息。

### 功能 5 — 加密儲存機密

您的 API 金鑰與其他敏感認證資料，在硬碟中皆經過高強度演算法（ChaCha20-Poly1305）**加密儲存**。即使有人不慎複製了您的設定檔，在沒有解密金鑰的情況下也無法讀取您的原始 API 金鑰。

### NullClaw 預設「無法」做到的事情

- 存取工作區資料夾以外的檔案
- 在未設定郵件憑證的情況下發送電子郵件
- 在沒有正確機器人 Token 的情況下向頻道發言
- 未經沙盒隔離擅自執行任意 Shell 指令
- 在沒有明確設定網路通道的情況下擅自將自身暴露給公開網際網路

## 7. 初學者常見錯誤

### 錯誤 1 — 在不了解原理的情況下將閘道暴露至網際網路

**發生了什麼事：** 您將 `gateway.host = "0.0.0.0"` 設定上去，想讓閘道隨處可連。預設情況下這會被刻意阻止。如果您強行覆寫且未正確設定配對認證與允許清單，網路上的陌生人將可以直接向您的 AI 下達指令。

**解決方法：** 請使用網路通道（例如 Cloudflare Tunnel、ngrok 或 Tailscale）而不是直接開放防火牆連接埠。通道能讓您從外網安全存取本機閘道，同時維持既有的安全控制。

### 錯誤 2 — 在公開頻道上設定了空的允許清單

**發生了什麼事：** 您串接了 Telegram 機器人，但 `allow_from` 保持空白。結果沒有任何人能向它傳送訊息。

**解決方法：** 將 `allow_from` 設定為允許與機器人交談的使用者 Telegram ID。您可以在 Telegram 上使用 `@userinfobot` 查詢您自己的使用者 ID。

### 錯誤 3 — API 金鑰與 Provider 不匹配

**發生了什麼事：** 您貼上了 OpenAI 的金鑰，但設定檔中的 Provider 卻填寫 `openrouter`。NullClaw 會直接拒絕，因為 OpenRouter 與 OpenAI 的金鑰格式完全不同。

**解決方法：** 請確保 Provider 名稱與金鑰所屬的服務完全對應。OpenRouter 金鑰以 `sk-or-` 開頭，OpenAI 金鑰以 `sk-` 開頭。

### 錯誤 4 — 忘記讓閘道保持運作

**發生了什麼事：** 您在 CLI 模式下進行對話（`nullclaw agent`），但卻期待它同時在 Telegram 上回覆訊息。CLI 模式與閘道模式是分開的——必須啟動閘道服務，頻道訊息才能正常收發。

**解決方法：** 在另一個終端機視窗中持續執行閘道，或將其安裝為背景服務（`nullclaw service start`）。使用 `nullclaw service status` 檢查服務是否正在運作。

### 錯誤 5 — 在不適當的地方儲存機密資訊

**發生了什麼事：** 您使用 `/memory-store` 要求 NullClaw 記住您的個人密碼。雖然記憶體在磁碟中是靜態加密的，但在使用期間會被解密載入到記憶體中。

**解決方法：** 真正極度敏感的資料請使用機密管理功能，而記憶體系統應僅用於儲存一般偏好設定與非敏感事實。

## 8. 通俗易懂的疑難排解

| 異常現象 | 可能原因 | 嘗試解決方法 |
|---|---|---|
| "API key invalid"（金鑰無效）錯誤 | 金鑰錯誤、Provider 設定不符或金鑰已過期 | 執行 `nullclaw onboard --interactive` 重新輸入金鑰 |
| Telegram 機器人沒有任何回應 | Bot Token 填錯、Webhook 未設定或機器人未啟動 | 執行 `nullclaw channel start telegram` 並在 Telegram 檢查機器人的隱私設定 |
| 閘道無法啟動 | 連接埠 3000 已被其他程式佔用 | 透過 `nullclaw gateway --port 3001` 更換連接埠 |
| AI 能回覆但記不住上一句說過的話 | 連線階段紀錄未載入或記憶體功能未生效 | 檢查設定檔中的 `memory.auto_save` 是否設為 `true` |
| NullClaw 提示找不到特定檔案 | 該檔案位於工作區目錄之外 | 將檔案移動至工作區內，或檢查您的 `allowed_paths` 設定 |
| 速率限制錯誤（429 Rate Limit） | 超過了 AI Provider 的使用量或頻率上限 | 請稍候再試，或切換至其他 Provider / Model |

### 萬用診斷指令

執行以下指令可進行全方位的健全狀態檢查：

```bash
nullclaw doctor
```

它會依序檢查設定檔語法、API 金鑰有效性、頻道連線狀態、記憶體狀態等。如果您需要尋求協助除錯，將此指令的輸出結果提供給社群將非常有幫助。

## 9. 詞彙表

| 術語 | 白話解釋 |
|---|---|
| **API Key（API 金鑰）** | 一串密碼，讓 NullClaw 能合法呼叫外部 AI 服務。請務必保密。 |
| **Channel（頻道）** | 訊息傳入 NullClaw 的管道——如 Telegram、Discord、Email 等。 |
| **Gateway（閘道）** | 中央樞紐路由器，負責在通訊頻道與 AI 之間派送轉發訊息。 |
| **Provider（提供商）** | NullClaw 連接的 AI 雲端服務商——OpenRouter、OpenAI、Anthropic 等。 |
| **Model（模型）** | 用於特定任務的具體 AI 大腦——Claude Sonnet、GPT-4o、Llama 等。 |
| **Workspace（工作區）** | 您電腦上的特定資料夾，NullClaw 僅被允許存取此目錄內的檔案。 |
| **Sandbox（沙盒）** | 一個受限制的執行環境，防止指令對作業系統造成破壞或危害。 |
| **Pairing（配對）** | 一組安全驗證碼，防止未經授權的陌生人擅自使用您的閘道。 |
| **Allowlist（允許清單）** | 獲准在特定頻道向機器人發送訊息的使用者白名單。 |
| **Tunnel（網路通道）** | 一條安全的加密通道，將您本機的閘道安全地暴露給網際網路存取。 |
| **Memory（記憶體）** | NullClaw 的長期記憶儲存庫，在跨對話中記錄事實與使用者偏好。 |
| **Tool（工具）** | NullClaw 具備的實體功能——讀取檔案、執行指令、發送訊息等。 |
| **Agent（代理人）** | 一個具備獨立身分、模型與工作區的 NullClaw 設定執行個體。 |
| **vtable（虛擬函式表）** | （技術術語）一種無需修改呼叫端程式碼即可抽換底層實作的架構模式。一般日常使用無需理解此概念。 |
