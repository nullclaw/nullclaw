## 1. NullClaw とは？

**一言でいうと:** NullClaw は、あなた自身のマシン上だけで動作する、小さく、高速で、安全な AI アシスタントです。AI モデルは内蔵されていません。OpenRouter、OpenAI、Anthropic など、あなたが選んで料金を支払うモデルに接続して使います。

次のように考えてみてください。

| たとえ | 意味 |
|---|---|
| NullClaw は **頭脳** | 聞き、考え、計画し、行動します。 |
| AI プロバイダー（OpenRouter など）は **知識エンジン** | テキストを生成し、質問に答え、画像を処理します。 |
| **チャンネル**（Telegram、Discord など）は NullClaw と話すための手段 | メールかテキストメッセージかを選ぶようなものです。チャンネルがメッセージを運びます。 |

**ChatGPT を開くだけではなく、なぜこれを使うのでしょうか？**

| ユースケース | ChatGPT | NullClaw |
|---|---|---|
| Telegram や Discord でボットとチャットする | いいえ | はい — 直接接続します |
| コンピューター上のファイルを読み書きする AI | 非常に限定的 | はい — フルアクセス |
| シェルコマンドを実行する AI | いいえ | はい — 安全にサンドボックス化 |
| 5ドルの Raspberry Pi で動作する | いいえ | はい |
| すべてのデータを自分のマシンに保持する | いいえ | はい |
| 自分のインフラに接続する | いいえ | はい |
| API キーなしで 100% オフライン動作 | いいえ | いいえ — API キーが必要です |

NullClaw は、自分の条件で、自分のハードウェア上で、自分のツールやチャンネルにつながって動く AI を求める **パワーユーザー** や **開発者** に最適です。

## 2. NullClaw に頼めること

設定が完了すると、NullClaw は幅広いタスクをこなせます。日常的な言葉で表した例をいくつか紹介します。

**情報収集とリサーチ**
- 「この URL の記事を要約して」
- 「今日の東京の天気は？」（Web 検索ツール経由）
- 「プロジェクト X に関する先週のメールをすべて探して」

**ファイル操作**
- 「ワークスペースにある notes.md というファイルを読んで」
- 「会議の要約を meeting-notes.md に書いて」
- 「会議メモを日次ログに追記して」
- 「README を編集してインストール手順を追加して」

**シェルとシステム**
- 「ディスクの空き容量がどれくらいあるか確認して」
- 「サーバーログの最後の 50 行を見せて」
- 「バックアップスクリプトを実行して、成功したかどうか教えて」

**コーディングと開発**
- 「CSV を読み込んで棒グラフを出力する Python スクリプトを書いて」
- 「このエラーメッセージの意味を説明して」
- 「ログイン関数のユニットテストを追加して」

**自動化**
- 「毎日午前 9 時に、サーバーのステータスを確認するようリマインドして」
- 「Telegram で 'deploy' を含むメッセージを送ったら、デプロイスクリプトを実行して」
- 「この大事なメモをメモリに保存して、聞いたときに思い出して」

**コミュニケーションチャンネル**
- 「私の Discord チャンネルにメッセージを送って」
- 「今メッセージをくれた Telegram ユーザーに返信して」
- 「Slack チャンネルに最新情報を投稿して」

**ハードウェア（上級）**
- 「Raspberry Pi に接続したセンサーから温度を読み取って」
- 「Arduino の 13 番ピンの LED を点滅させて」

## 3. メンタルモデル: 全体がどうつながっているか

何かを設定する前に、3 つの構成要素を理解しておくと役立ちます。

### パート 1 — チャットインターフェース（NullClaw と話す方法）

NullClaw とやり取りする方法は 2 つあります。

**CLI モード（コマンドライン）:** ターミナルウィンドウにメッセージを入力します。ちょっとしたタスクやテストに向いています。

```bash
nullclaw agent -m "What is 2 + 2?"
```

**インタラクティブモード:** 開いたままになる、より会話的なセッションです。

```bash
nullclaw agent
# then type your messages
```

**ゲートウェイモード:** 最も強力なセットアップです。メッセージを待ち受けるローカル Web サーバーを起動します。他のプログラムやチャンネル（Telegram、Discord など）がそこに接続し、ユーザーからのメッセージを届けられます。NullClaw に Telegram や Discord の中で応答させるには、この方法を使います。

```bash
nullclaw gateway
# runs at http://127.0.0.1:3000
```

### パート 2 — チャンネル（メッセージの出入り口）

**チャンネル** は、NullClaw とメッセージングサービスをつなぐ橋です。電話回線のようなものだと考えてください。チャンネルごとに別の電話番号があるイメージです。

NullClaw は多くのチャンネルに標準で対応しています。

| チャンネル | 接続先 |
|---|---|
| CLI | ターミナル（外部接続なし） |
| Telegram | あなたの Telegram ボット |
| Discord | あなたの Discord ボット |
| Signal | あなたの Signal アカウント |
| Slack | あなたの Slack ワークスペース |
| WhatsApp | あなたの WhatsApp Business アカウント |
| Email | メールの受信箱と送信メール |
| Matrix | Matrix/Element のメッセージング |
| Nostr | Nostr 分散型プロトコル |
| Webhook | 任意の HTTP エンドポイント（カスタム連携用） |
| IRC | Internet Relay Chat |
| Lark / Feishu | Lark/Feishu ワークスペース |
| DingTalk | DingTalk ワークスペース |
| QQ | QQ メッセージング |
| iMessage | macOS の iMessage |
| Mattermost | Mattermost のセルフホスト型チャット |

**重要なセキュリティの考え方:** デフォルトでは、チャンネルはあなたが指定した承認済みユーザーのリストからのメッセージだけを受け付けます。許可リストが空のチャンネルは誰も受け付けません。これは意図的なもので、見知らぬ人があなたの AI を操作するのを防ぎます。

### パート 3 — ゲートウェイ（メッセージルーター）

**ゲートウェイ** は、次の役割を担う中央ハブです。
1. チャンネル（Telegram、Discord など）からメッセージを受け取る
2. それを AI に送って処理させる
3. AI の応答を正しいチャンネルを通じて返す

```
User sends message
       ↓
   Channel (Telegram/Discord/etc.)
       ↓
   Gateway (message router at :3000)
       ↓
   AI Model (OpenRouter/OpenAI/etc.)
       ↓
   NullClaw Brain (thinks, uses tools, decides)
       ↓
   Response
       ↓
   Gateway → Channel → User
```

デフォルトでは、ゲートウェイはローカルマシン（`127.0.0.1:3000`）でのみ待ち受けます。つまり、あなたのコンピューターの外からは誰もアクセスできません。外部からのアクセスを許可する（たとえばインターネットから Telegram のメッセージを受け取る）には、**トンネル** を使います。トンネルとは、Cloudflare や ngrok などのサービスを通じて、ローカルのゲートウェイを外部に安全に公開する仕組みです。

## 4. 5 分で始める

### ステップ 1 — API キーを取得する

NullClaw が考えるには AI モデルが必要です。API キーはあなたが用意します。最も簡単な始め方は **OpenRouter** で、1 つのアカウントで多くのモデルを利用できます。

1. [openrouter.ai](https://openrouter.ai) にアクセスして、無料アカウントを作成します。
2. **Keys** に移動して、新しい API キーを作成します。キーをコピーしてください。表示されるのは一度きりです。
3. （任意）AI が実際に応答できるよう、アカウントにクレジットを追加します。5 ドルでもすべてを試すには十分です。

> **API キーとは？** パスワードのようなものだと考えてください。あなたが本人であることを AI サービスに証明し、利用量を記録します。大切に保管してください。キーを持っている人は誰でもあなたのアカウントを使えてしまいます。

### ステップ 2 — NullClaw をインストールする

**macOS / Linux（推奨）:**

```bash
brew install nullclaw
```

**Windows:**

[NullClaw のリリースページ](https://github.com/nullclaw/nullclaw/releases) から Windows 用の `.zip` アーカイブをダウンロードして展開し、同梱の `nullclaw.exe` をわかりやすい場所に置いてください。

**ソースから（全プラットフォーム）:**

```bash
git clone https://github.com/nullclaw/nullclaw.git
cd nullclaw
zig build -Doptimize=ReleaseSmall
# binary will be at zig-out/bin/nullclaw
```

### ステップ 3 — 設定する

インタラクティブなセットアップウィザードを実行します。

```bash
nullclaw onboard --interactive
```

ウィザードがいくつか質問をします。各質問の意味は次のとおりです。

| 質問 | 答え方 |
|---|---|
| Provider | `openrouter` を選択します |
| API Key | OpenRouter のキーを貼り付けます |
| Default model | Enter を押して提案されたモデルを受け入れます |
| Workspace directory | Enter を押してデフォルトを使用します（NullClaw がファイルを保存する場所） |
| Gateway host | Enter を押します（ローカルのままで安全です） |
| Gateway port | Enter を押します（デフォルトは 3000） |
| Enable channels? | まず CLI モードを試したいだけなら `n` と入力します |

### ステップ 4 — テストする

```bash
nullclaw agent -m "Hello! Can you explain what you are?"
```

数秒以内に AI から応答が返ってくるはずです。

### ステップ 5 — ゲートウェイを起動する

NullClaw に Telegram、Discord、またはその他のチャンネルからのメッセージを待ち受けさせたい場合:

```bash
nullclaw gateway
```

ゲートウェイが `127.0.0.1:3000` で実行中であることを示す出力が表示されます。

停止するには `Ctrl+C` を押します。

## 5. メモリの仕組み

NullClaw にはメモリシステムが組み込まれています。つまり、会話をまたいで、あなたが伝えたことを覚えておけます。

### メモリの保存方法

メモリはあなたのコンピューター上のローカルデータベースに保存されます（デフォルトでは `~/.nullclaw/memory.db` にある SQLite データベース）。別の場所を使うには `memory.database_path` を設定してください。相対パスはワークスペースディレクトリを基準に解決されます。リモートのメモリバックエンドを使うよう設定しない限り、クラウドには何も送信されません。

### メモリ操作の種類

| コマンド | 機能 |
|---|---|
| `/memory-store <fact>` | 事実を長期メモリに保存します |
| `/memory-recall <topic>` | トピックに関連する事実を取り出します |
| `/memory-forget <fact>` | 特定の事実をメモリから削除します |
| `/memory-list` | 現在メモリにあるものをすべて一覧表示します |
| `/scratch` | ちょっとしたメモ用の一時的なメモ帳を開きます |

### 会話の例

```
You: Remember that my server's admin password is SuperSecret123.
NullClaw: Done. I've stored that fact securely in memory.

You: What did I tell you about my server?
NullClaw: You mentioned that your server's admin password is SuperSecret123.
```

### メモリを消去するタイミング

- うっかり機密情報を伝えてしまった → `/memory-forget` を使うか、NullClaw に削除を頼みます。
- メモリの内容が不正確になった → 修正した内容で更新します。
- 最初からやり直したい → `nullclaw memory purge` を実行してすべてを消去します。

> **プライバシーに関する注意:** デフォルトでは、すべてのメモリデータはあなたのマシンに保存されたままです。リモートのメモリバックエンドを明示的に設定しない限り、NullClaw が会話履歴やメモリの内容を AI プロバイダーに送信することはありません。

## 6. 安全に使うために

NullClaw にはいくつかの安全機能が組み込まれています。技術的な詳細を理解する必要はありません。そうした機能があることだけ知っておいてください。

### 機能 1 — ワークスペースの分離（アクセスできるファイル）

デフォルトでは、NullClaw は **ワークスペース** と呼ばれる特定のフォルダー内のファイルしか読み書きできません。ファイルシステム全体にはアクセスできません。これにより、パスワード、SSH キー、個人的な書類などの機密ファイルを誤って読み取ることを防ぎます。

ワークスペースは通常 `~/.nullclaw/workspace/` です。設定で変更できます。

### 機能 2 — サンドボックス（実行できるコマンド）

NullClaw がシェルコマンド（`ls` や `git` など）を実行する必要があるときは、**サンドボックス** の中で実行します。サンドボックスとは、コマンドができることを制限した環境です。サンドボックス内では次のことができません。
- ワークスペース外のファイルへのアクセス
- システム設定の変更
- ソフトウェアのインストール
- 他のユーザーのデータへのアクセス

### 機能 3 — ペアリング（ゲートウェイを使える人）

ゲートウェイの実行中は、**ペアリング** が使われます。ペアリングとは、接続する人に有効なペアリングコードの提示を求めるセキュリティチェックです。これにより、見知らぬ人がゲートウェイを通じてあなたの NullClaw にコマンドを送るのを防ぎます。

### 機能 4 — チャンネルの許可リスト（話しかけられるユーザー）

各メッセージングチャンネルには **許可リスト** があります。これは承認されたユーザー ID またはユーザー名のリストです。許可リストに載っているユーザーだけが、そのチャンネルを通じて NullClaw にメッセージを送れます。許可リストが空のチャンネルは誰も受け付けません。

### 機能 5 — 暗号化されたシークレット

API キーやその他の機密性の高い認証情報は、強力な暗号化アルゴリズム（ChaCha20-Poly1305）を使ってディスク上に **暗号化** して保存されます。誰かがあなたの設定ファイルをコピーしても、暗号鍵がなければ API キーを読み取ることはできません。

### デフォルトで NullClaw ができないこと

- ワークスペース外のファイルへのアクセス
- メールの認証情報を設定していない状態でのメール送信
- 適切なボットトークンがない状態でのチャンネルへの投稿
- サンドボックスを経由しない任意のシェルコマンドの実行
- 明示的なトンネル設定なしでの公開インターネットへの露出

## 7. 初心者によくある間違い

### 間違い 1 — 理解しないままゲートウェイをインターネットに公開する

**何が起こるか:** どこからでもゲートウェイにアクセスできるよう `gateway.host = "0.0.0.0"` を設定したとします。これはデフォルトでは意図的にブロックされています。ペアリングと許可リストを設定しないままこれを上書きすると、見知らぬ人があなたの AI にコマンドを送れてしまう可能性があります。

**対処法:** ポートを直接開くのではなく、トンネル（Cloudflare Tunnel、ngrok、または Tailscale）を使ってください。トンネルを使えば、セキュリティ制御を維持したまま、外部からローカルのゲートウェイにアクセスできます。

### 間違い 2 — 公開チャンネルの許可リストが空

**何が起こるか:** Telegram ボットを接続したものの、`allow_from` を空のままにしています。誰もボットにメッセージを送れません。

**対処法:** ボットとの会話を許可すべき人の Telegram ユーザー ID を `allow_from` に設定してください。自分のユーザー ID を調べるには、Telegram で `@userinfobot` を使います。

### 間違い 3 — API キーに対してプロバイダーが間違っている

**何が起こるか:** OpenAI のキーを貼り付けたのに、設定ではプロバイダーを `openrouter` にしています。OpenRouter と OpenAI ではキーの形式が異なるため、NullClaw はそれを拒否します。

**対処法:** プロバイダー名を、キーが属するサービスに合わせてください。OpenRouter のキーは `sk-or-` で始まり、OpenAI のキーは `sk-` で始まります。

### 間違い 4 — ゲートウェイを実行したままにしておくのを忘れる

**何が起こるか:** CLI（`nullclaw agent`）で会話を始めたのに、Telegram のメッセージに応答することを期待しています。CLI モードとゲートウェイモードは別物です。チャンネル経由のメッセージを機能させるには、ゲートウェイが実行中である必要があります。

**対処法:** ゲートウェイをターミナルウィンドウで実行し続けるか、バックグラウンドサービス（`nullclaw service start`）として実行してください。実行中かどうかは `nullclaw service status` で確認できます。

### 間違い 5 — 機密情報を間違った場所に保存する

**何が起こるか:** `/memory-store` を使って、NullClaw にパスワードを覚えさせようとします。メモリは保存時には暗号化されていますが、使用中はメモリ上で復号されます。

**対処法:** 本当に機密性の高いデータにはシークレット管理機能を使い、メモリシステムは機密性のない好みや事実のためだけに使ってください。

## 8. やさしい言葉で解説するトラブルシューティング

| 症状 | 考えられる原因 | 試すこと |
|---|---|---|
| 「API key invalid」エラー | キーの誤り、プロバイダーの誤り、またはキーの期限切れ | `nullclaw onboard --interactive` を実行してキーを再入力します |
| Telegram ボットから応答がない | ボットトークンの誤り、webhook が未設定、またはボットが起動していない | `nullclaw channel start telegram` を実行し、Telegram でボットのプライバシー設定を確認します |
| ゲートウェイが起動しない | ポート 3000 がすでに使用中 | `nullclaw gateway --port 3001` でポートを変更します |
| AI は応答するが以前のメッセージを覚えていない | セッション履歴が読み込まれていない、またはメモリが機能していない | 設定で `memory.auto_save` が `true` になっているか確認します |
| NullClaw がファイルを見つけられないと言う | ファイルがワークスペースの外にある | ファイルをワークスペース内に移動するか、`allowed_paths` の設定を確認します |
| レート制限エラー（429） | API プロバイダーの利用上限に達した | しばらく待つか、別のプロバイダー/モデルに切り替えます |

### 診断コマンド

完全なヘルスチェックを行うには、次を実行します。

```bash
nullclaw doctor
```

設定の妥当性、API キー、チャンネルのステータス、メモリなど、すべてをチェックします。デバッグの手助けが必要なときは、この出力を共有してください。

## 9. 用語集

| 用語 | やさしい言葉での定義 |
|---|---|
| **API キー** | NullClaw が AI サービスと通信するためのパスワード。秘密にしておいてください。 |
| **チャンネル** | メッセージが NullClaw に届く手段 — Telegram、Discord、メールなど。 |
| **ゲートウェイ** | チャンネルと AI の間でメッセージをやり取りする中央ハブ。 |
| **プロバイダー** | NullClaw が接続する AI サービス — OpenRouter、OpenAI、Anthropic など。 |
| **モデル** | タスクに使われる具体的な AI の頭脳 — Claude Sonnet、GPT-4o、Llama など。 |
| **ワークスペース** | NullClaw がアクセスを許可されている、コンピューター上の特定のフォルダー。 |
| **サンドボックス** | コマンドが有害なことをするのを防ぐ、制限された環境。 |
| **ペアリング** | 見知らぬ人があなたのゲートウェイを使うのを防ぐセキュリティコード。 |
| **許可リスト** | チャンネルにメッセージを送ることを許可された承認済みユーザーのリスト。 |
| **トンネル** | ローカルのゲートウェイをインターネットに安全に公開する仕組み。 |
| **メモリ** | 会話をまたいで事実や好みを保存する、NullClaw の長期ストレージ。 |
| **ツール** | NullClaw が使える機能 — ファイルの読み取り、コマンドの実行、メッセージの送信など。 |
| **エージェント** | 独自のアイデンティティ、モデル、ワークスペースを持つ、設定済みの NullClaw インスタンス。 |
| **vtable** | （技術用語）呼び出し側のコードを変えずに実装を差し替えるためのパターン。NullClaw を使うためにこれを理解する必要はありません。 |
